# इनपुट

लगभग सभी सिस्टम पर **SDL2** कीबोर्ड, माउस, उंगलियाँ और कंट्रोलर देता है, और एडिटर और गेम उन्हीं इवेंट पर लिखे गए हैं। जो SDL नहीं संभालता, उसे Core पूरा करता है:

| क्या | कैसे आता है |
|---|---|
| टच | Android, ब्राउज़र, Vita और 3DS पर SDL। Symbian पर `W3dTactil` वही रूपांतरण करता है जो SDL करता है (पहली उंगली एक माउस चलाती है, बाकी उंगलियों के रूप में सूचना देती हैं): S60 5th पर एक उंगली, N8 पर मल्टी-टच |
| झुकाव | N95 पर Nokia का Sensor API, जो शुरू होते समय लोड होता है (इसके बिना भी गेम वैसे ही चलता है)। Android और PC पर यह SDL से आता है |
| कंट्रोलर | बाकी पर SDL। Symbian पर, Bluetooth से PS3 और PS4 के जॉयस्टिक (bthid-s60 ड्राइवर), बटनों के उसी क्रम में जो SDL में है। अधिकतम 4 |
| वाइब्रेशन | Android, फ़ोन के वाइब्रेटर से। ब्राउज़र, `navigator.vibrate` (iOS पर, एक तरकीब से सिस्टम का "टिक")। डेस्कटॉप: कुछ नहीं। API ज़्यादा वादा नहीं करती: "एक छोटा झटका, अगर हो सके" |
| क्लिपबोर्ड | SDL (ब्राउज़र वाला भी); Symbian पर `CClipboard` |

बिना टचस्क्रीन वाले कंसोल (PSP, Dreamcast) पर कंट्रोलर एक कर्सर चलाता है, माउस की तरह।

यह क्यों ज़रूरी है: Symbian के टच वाले जेस्चर उसी रास्ते से गुज़रते हैं जिससे Android के, इसलिए Android में जेस्चर का कोई सुधार अपने आप फ़ोन तक पहुँच जाता है। Lua से: [कीबोर्ड, कंट्रोलर, टच और माउस](../lua/api-entrada.md)।
