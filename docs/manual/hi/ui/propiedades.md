# कार्ड और प्रॉपर्टी

## कार्ड

`GroupPropertie` (`Propieties/GroupPropertie.h`) एक शीर्षक और पंक्तियों वाला कार्ड है। हर पंक्ति एक प्रॉपर्टी है, एक क्लास जो `PropertieBase` से इनहेरिट करती है और आपके एक वेरिएबल की ओर इशारा करती है: कार्ड उसे दिखाता है और वहीं बदलता है।

```cpp
GroupPropertie* jugador = new GroupPropertie("Jugador");
jugador->icono = IconType::gamepad;        // वैकल्पिक: ऐरो और शीर्षक के बीच

PropFloat* vel = new PropFloat("Velocidad", " m/s");
vel->value = &velocidad;
jugador->properties.push_back(vel);

jugador->Resize(ancho, 0);    // ऊँचाई कार्ड ख़ुद गणना करता है
jugador->Render();            // मौजूदा ओरिजिन पर
```

कार्ड अपनी पंक्तियों का मालिक है: उसे डिलीट करने पर, वह उन्हें भी डिलीट कर देता है।

- शीर्षक में उसे फ़ोल्ड करने के लिए एक ऐरो होता है (`open`)। `flecha = false` के साथ यह नहीं होता: किसी तैरती विंडो के लिए।
- नीचे दो कॉलम हैं: बाईं ओर लेबल और दाईं ओर मान। `anchoValores` चौड़ाई का वह हिस्सा है जो मान लेता है: डिफ़ॉल्ट 0.5।
- `reservaKeyBtn = true` सबसे दाईं ओर एनिमेशन वाले डायमंड के लिए एक कॉलम छोड़ता है।
- लगभग सभी पंक्तियाँ एक पंक्ति की ऊँचाई और एक `gap` के बराबर होती हैं। बिना वेरिएबल वाला (`value` `NULL` में) नंबर, चेकबॉक्स या रंग न जगह लेता है न ड्रॉ होता है।
- `visible = false` पूरा कार्ड छिपा देता है।

चुनी हुई पंक्ति में लेबल `accent` में, मान सफ़ेद में और बॉर्डर सफ़ेद होती है; एडिट होते समय, मान और बॉर्डर `accent` हो जाते हैं। माउस के नीचे वाली पंक्ति सफ़ेद में होती है: उसे वह चिह्नित करता है जिसमें कार्ड है, `PropHoverGroup` और `PropHoverFila` से।

## चुनना और एडिट करना

`selectIndex` चुनी हुई पंक्ति है: `-2` कोई नहीं, `-1` शीर्षक, `0` से आगे एक पंक्ति।

| फ़ंक्शन | क्या करता है |
|---|---|
| `NextSelect()`, `PrevSelect()` | नीचे वाली या ऊपर वाली पंक्ति पर जाते हैं। ख़ाली जगहों और बिना वेरिएबल वाली पंक्तियों को छोड़ देते हैं। कार्ड से बाहर निकलने पर `true` लौटाते हैं, ताकि अगले पर जाया जा सके |
| `EnterPropertieSelect()` | शीर्षक पर, कार्ड को फ़ोल्ड या अनफ़ोल्ड करता है। किसी पंक्ति पर, उसे एडिट करता है |
| `button_up()`, `button_down()`, `button_left()`, `button_right()` | एडिट होते समय, पंक्ति के पास जाते हैं |
| `Cancel()` | पंक्ति को वैसा ही छोड़ देता है जैसी वह थी |

`editando` बताता है कि कोई पंक्ति एडिट हो रही है या नहीं। इससे, ऐरो मान बदलते हैं या चुनाव को हिलाते हैं:

```cpp
if (jugador->editando) jugador->button_up();   // मान बदलता है
else jugador->PrevSelect();                    // ऊपर वाली पंक्ति
```

माउस वह संभालता है जिसमें कार्ड है: कार्ड को नहीं पता कि वह स्क्रीन पर कहाँ है। ऊपर बॉर्डर (`borderGS`) और शीर्षक (`RenglonHeightGS + gapGS`) हैं। हर पंक्ति उतनी होती है जितना उसका `Resize(ancho)` लौटाता है।

## पंक्तियाँ

| क्लास | क्या है | कैसे एडिट होती है |
|---|---|---|
| `PropFloat` | एक नंबर | ऐरो से, या टाइप करके |
| `PropBool` | एक चेकबॉक्स, दाईं ओर सटा हुआ | OK उसे चालू या बंद करता है |
| `PropColor` | रंग का एक वर्ग, दाईं ओर सटा हुआ | OK एडिट मोड में जाता है और रंग सेव कर लेता है, कैंसल होने की स्थिति के लिए |
| `PropButton` | एक बटन | OK उसका ऐक्शन कॉल करता है |
| `PropButtonRow` | एक पंक्ति में कई बटन | बायाँ और दायाँ एक चुनते हैं; OK उसे दबाता है |
| `PropText` | एक टेक्स्ट बॉक्स | OK लिखने के लिए उस पर फ़ोकस करता है |
| `PropListMeshParts` | स्क्रॉल वाली एक सूची | ऊपर और नीचे चुनते हैं |
| `PropLabel` | पढ़ने के लिए एक टेक्स्ट, एक या कई लाइनों में | चुना नहीं जाता |
| `PropSeparator` | एक लाइन | चुना नहीं जाता |
| `PropGap` | एक `gap` की ख़ाली जगह | चुना नहीं जाता |
| `PropSelectText` | अपने लेबल वाला एक बॉक्स, बिना मान के | अभी कुछ नहीं करता |

### नंबर

```cpp
PropFloat* vida = new PropFloat("Vida");
vida->value = &vidaJugador;
vida->SetRango(0, 100);           // इससे आगे नहीं जाता
vida->entero = true;              // पूर्णांकों में दिखता और बढ़ता है
vida->stepFino = 1;               // ऊपर और नीचे
vida->stepGrueso = 10;            // बाएँ और दाएँ
vida->onChange = AlCambiarVida;   // void AlCambiarVida()
```

| फ़ील्ड | क्या करता है |
|---|---|
| `unit` | नंबर से जुड़ा एक टेक्स्ट, जैसे `°`। यह कंस्ट्रक्टर का दूसरा आर्ग्युमेंट है |
| `stepFino`, `stepGrueso` | ऐरो कितना जोड़ते हैं: डिफ़ॉल्ट 0.01 और 0.1 |
| `entero` | नंबर को राउंड करके दिखाता है, और ऐरो राउंड किए हुए से शुरू होते हैं। इसके बिना इसमें चार दशमलव अंक होते हैं |
| `centrado` | नंबर अपने बॉक्स के बीच में |
| `flechas` | दोनों तरफ़ `<` और `>` ड्रॉ करता है। उन पर क्लिक कंटेनर संभालता है |
| `opciones`, `nOpciones` | `entero` के साथ: नंबर एक इंडेक्स है और उस विकल्प का नाम दिखता है, `W3dMenuTraducir` से अनुवादित |
| `acelera` | बायाँ और दायाँ 1-1 से शुरू होते हैं और, दोहराने पर, 10 तक बढ़ते हैं |
| `dragStep` | ड्रैग करते समय हर पिक्सेल पर कितना बदलता है। ड्रैग कंटेनर करता है |

`Set(v)` मान को रेंज के अंदर सेट करता है और `onChange` कॉल करता है। ऐरो इसी से होकर जाते हैं।

इसे टाइप करने के लिए:

```cpp
vida->IniciarEdicionTexto();   // मान दिखाता है, पूरा चुना हुआ
// कुंजियाँ g_textFieldActivo के पास जाती हैं: इनपुट और टेक्स्ट बॉक्स देखें
NumEditCommit();               // Enter: इसे लागू करता है
NumEditCancel();               // Esc: जैसा था वैसा रहता है
```

`NumEditActivo()` बताता है कि कोई नंबर एडिट हो रहा है या नहीं। जो टेक्स्ट नंबर नहीं है, उसका मान 0 होता है।

### चेकबॉक्स

`value` एक `bool` की ओर इशारा करता है। हर बार बदलने पर `onChange` कॉल होता है। लेबल अपनी बाईं ओर की पूरी जगह लेता है और, अगर नहीं समाता, तो `..` के साथ कट जाता है।

### रंग

`value` चार `float` (RGBA) की ओर इशारा करता है। UI वर्ग ड्रॉ करती है; कलर पिकर UI का नहीं है। एडिट होते समय, ऐरो सिर्फ़ पहला कंपोनेंट बदलते हैं।

### बटन

`action` वह फ़ंक्शन है जिसे यह कॉल करता है। `gris = true` इसे धुंधला कर देता है और यह कुछ नहीं करता। `oculto = true` पंक्ति नहीं लेता।

`conLabel = true` के साथ, पंक्ति एक नाम और एक बटन होती है: नाम बाईं ओर, अपने टेक्स्ट की चौड़ाई का, पंक्ति के 55 % तक, और बटन बाकी पूरी जगह में। `labelChars` नाम की चौड़ाई तय करता है, ताकि कई पंक्तियाँ एक सीध में रहें। `button->desplegable` के साथ इसमें मेनू वाला छोटा ऐरो होता है। इसके अलावा:

- `AgregarPrefijo(accion, ayuda)` बटन से पहले एक वर्ग रखता है, कोई रंग दिखाने के लिए।
- `AgregarExtra(icono, accion, ayuda)` दाईं ओर सिर्फ़ आइकन वाले अधिकतम दो छोटे बटन रखता है। `slotsExtras` उनके लिए जगह आरक्षित करता है, ताकि वे पंक्तियों के बीच एक सीध में रहें। `ExtraEnX(x)` बताता है कि उस x पर कौन-सा है, क्लिक के लिए।

### बटनों की पंक्ति

```cpp
PropButtonRow* fila = new PropButtonRow();
fila->Agregar("Aceptar", Aceptar);
fila->Agregar("Cancelar", Cancelar);
jugador->properties.push_back(fila);
```

बटन चौड़ाई को बराबर हिस्सों में बाँट लेते हैं। अदृश्य बटन छोड़ दिए जाते हैं और बाकी उनकी जगह आपस में बाँट लेते हैं। `Disparar(i)` बटन `i` को दबाता है: इसे कंटेनर तब कॉल करता है जब क्लिक उस हिस्से पर पड़ता है।

### टेक्स्ट बॉक्स

```cpp
PropText* nombre = new PropText("Nombre", "Jugador 1");
// nombre->field.text में वह है जो लिखा गया
```

`onClick`: एडिट करने की जगह, उस फ़ंक्शन को कॉल करता है, जैसे कोई फ़ाइल एक्सप्लोरर खोलने के लिए। `error = true` चुनी हुई पंक्ति की बॉर्डर को लाल कर देता है, जब तक कुछ लिखा न जाए। `oculto = true` पंक्ति नहीं लेता। OK इस पर `TextFieldEnfocar` से फ़ोकस करता है, जो आज एडिटर में परिभाषित है। लिखने के लिए [इनपुट और टेक्स्ट बॉक्स](entrada.md) देखें।

### टेक्स्ट

`PropLabel("texto")` एक लाइन है। `PropLabel("texto", true)` स्पेस पर तोड़ता है ताकि टेक्स्ट चौड़ाई में समा जाए; जो शब्द अकेले नहीं समाता वह पूरा रहता है। `rojo = true`, किसी एरर के लिए। `oculto = true` पंक्ति नहीं लेता।

### सूची

`PropListMeshParts` `filasMax` पंक्तियाँ दिखाता है, डिफ़ॉल्ट 3, और ज़्यादा होने पर एक छोटी बार के साथ। चुनी हुई पंक्ति हमेशा दिखती रहती है। `Cancel`, `selectIndex` को उसी पर लौटा देता है जो एडिट मोड में जाते समय था।

यह अभी किसी भी सूची के लिए काम नहीं आता: `modo` के अनुसार, यह सीन की एक सूची पढ़ता है (किसी मेश के हिस्से, उसके UV मैप, उसकी कलर लेयर, मॉडिफ़ायर, वर्टेक्स ग्रुप, हड्डियाँ, एनिमेशन, कंस्ट्रेंट, स्क्रिप्ट) या उसे एडिटर के फ़ंक्शन वाले हुक (`MixFila*`, `RutinaFila*`, `PostFila*`) से माँगता है।

## एनिमेशन वाला डायमंड

एक एनिमेट होने लायक पंक्ति (`animProp` 0 या उससे ज़्यादा, `PropFloat`, `PropBool`, `PropColor` और `PropButton` में) दाईं ओर एक डायमंड दिखाती है, अगर कार्ड में `reservaKeyBtn` है। उसका रंग स्थिति बताता है:

| स्थिति | रंग | मतलब |
|---|---|---|
| 0 | ग्रे | कोई एनिमेशन नहीं |
| 1 | `accent`, धीमी रोशनी में | एनिमेटेड, लेकिन यहाँ कोई कीफ़्रेम नहीं |
| 2 | `accent` | यहाँ एक कीफ़्रेम है |
| 3 | हरा | मान बदला और सेव नहीं हुआ |

डायमंड UI का है; उसकी स्थिति क्या है, यह नहीं। वह यह एक हुक से पूछता है जिसे प्रोग्राम इंस्टॉल करता है, और क्लिक दूसरे हुक को कॉल करता है:

```cpp
W3dKeyframeEstado = MiEstado;   // int MiEstado(int prop, int comp): 0 से 3 तक
W3dKeyframeToggle = MiToggle;   // void MiToggle(int prop, int comp): कीफ़्रेम जोड़ता या हटाता है
```

हुक के बिना, डायमंड ग्रे रहता है। कार्ड `W3dKeyframeToggle` को कॉल नहीं करता: उसे वह कॉल करता है जो क्लिक संभालता है। `g_kfFocoProp` उस पंक्ति की ओर इशारा करता है जिसके डायमंड पर कीबोर्ड का फ़ोकस है, और उसे सफ़ेद बॉर्डर से चिह्नित करता है। `W3dRenderRomboKey(estado)` एक अलग डायमंड ड्रॉ करता है।
