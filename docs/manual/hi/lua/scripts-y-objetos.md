# स्क्रिप्ट किसी ऑब्जेक्ट का एक कंपोनेंट है

Whisk3D में कोई स्क्रिप्ट हमेशा सीन के किसी **ऑब्जेक्ट** की होती है (एक मेश, एक एम्प्टी, एक 2D बटन…)। एक ऑब्जेक्ट में कई स्क्रिप्ट हो सकती हैं; हर स्क्रिप्ट अपने वेरिएबल के साथ अलग से चलती है, उसी क्रम में जिसमें वे दिखती हैं।

स्क्रिप्ट के अंदर, `yo()` उस ऑब्जेक्ट को लौटाता है जिसकी यह स्क्रिप्ट है। *दूसरे* ऑब्जेक्ट इस्तेमाल करने के लिए, स्क्रिप्ट `propiedades` नाम की एक ग्लोबल टेबल घोषित करती है। एडिटर उसे पढ़ता है और Properties पैनल में, स्क्रिप्ट के कार्ड में हर एंट्री के लिए एक फ़ील्ड दिखाता है:

```lua
propiedades = {
  pelota     = "objeto",                          -- सीन का कोई ऑब्जेक्ट चुनने के लिए एक फ़ील्ड
  dificultad = { "facil", "normal", "dificil" },  -- एक ड्रॉपडाउन सूची (पहला विकल्प डिफ़ॉल्ट है)
  velocidad  = 200,                               -- स्क्रिप्ट इस्तेमाल करने वाले हर ऑब्जेक्ट की अपनी एक संख्या
  activo     = true,                              -- एक हाँ/नहीं
  etiqueta   = "caja",                            -- एक टेक्स्ट
}

function inicio()
  local p   = objeto("pelota")         -- "pelota" फ़ील्ड में चुना गया ऑब्जेक्ट
  local dif = opcion("dificultad")     -- "facil", "normal" या "dificil"
  local v   = propiedad("velocidad")   -- 200, या उस ऑब्जेक्ट में जो भी डाला गया हो
end
```

> [!NOTE]
> `propiedades` पढ़ने के लिए एडिटर **फ़ाइल को चलाता है**, भले ही गेम न चल रहा हो। इसलिए फ़ंक्शन के बाहर सिर्फ़ घोषणाएँ रखें (टेबल, कॉन्स्टेंट, `local`), कभी भी ऐसा कोड नहीं जो कुछ करता हो।

Properties में स्क्रिप्ट के कार्ड में यह ऐसा दिखता है: हर प्रॉपर्टी के लिए एक फ़ील्ड, उसी क्रम में जिसमें वह कोड में है।

![Properties में स्क्रिप्ट का कार्ड: pelota (चुनने के लिए एक ऑब्जेक्ट), dificultad (एक सूची), velocidad (200), activo (टिक किया हुआ एक चेकबॉक्स) और etiqueta (caja)](../tutoriales/img/lua-propiedades.webp)

इस तरह, एक ही स्क्रिप्ट अलग-अलग वैल्यू वाले कई ऑब्जेक्ट के काम आती है: एक दुश्मन का `velocidad` फ़ील्ड 200 हो सकता है और दूसरे का 350।

## प्रॉपर्टी को रियल टाइम में बदलना

`propiedad("velocidad")` उसी पल की वैल्यू पढ़ता है। अगर आप गेम चलते समय उसे Properties में बदलते हैं, तो स्क्रिप्ट को अगले फ़्रेम में नई वैल्यू दिख जाती है, लेकिन सिर्फ़ तभी जब वह उसे `propiedad()` से दोबारा पढ़े। अगर आपने उसे किसी वेरिएबल में रख लिया था (`inicio()` में `local v = propiedad("velocidad")`), तो वेरिएबल में शुरुआत वाली वैल्यू ही रहती है।

```lua
function actualizar(dt)
  -- हर फ़्रेम में पढ़ा जाता है: गेम चलते समय Properties में आप जो बदलें, वह दिखता है
  mover(yo(), propiedad("velocidad") * dt, 0, 0)
end
```

हर फ़्रेम में `propiedad()` पढ़ना, वेरिएबल इस्तेमाल करने से धीमा है। पूरे गेम में इस तरह काम करना ठीक नहीं: वैल्यू सेट करते समय इसका इस्तेमाल करें, और जब वे तय हो जाएँ, तो उन्हें `inicio()` में वेरिएबल में रख लें।

## बटन

अगर कोई प्रॉपर्टी एक **फ़ंक्शन** है, तो कार्ड में एक **बटन** दिखता है: उसे दबाने पर वह फ़ंक्शन कॉल होता है। बटन पर नाम के बजाय कुछ और लिखा दिखाने के लिए, टेक्स्ट और फ़ंक्शन को एक टेबल में रखें:

```lua
propiedades = {
  velocidad = 90,
  cero = { "शून्य पर वापस", function()
    setRotacion(yo(), 0, 0, 0)
  end },
}
```

![velocidad और "शून्य पर वापस" बटन वाला स्क्रिप्ट का कार्ड](../tutoriales/img/lua-boton.webp)

गेम चलते समय फ़ंक्शन उसी स्क्रिप्ट में चलता है जो गेम में चल रही है। गेम के बिना, स्क्रिप्ट सिर्फ़ उस कॉल के लिए लोड होती है: इस तरह एक बटन **एडिटर के ऐड-ऑन** का काम करता है, जो सीन में कुछ करता है। जैसे, `seleccionados()` के साथ, यानी एडिटर में चुने हुए ऑब्जेक्ट के साथ:

```lua
propiedades = {
  subir = { "चुने हुए को ऊपर उठाएँ", function()
    for _, o in ipairs(seleccionados()) do
      mover(o, 0, 0, 1)   -- एक मीटर ऊपर
    end
  end },
}
```

> [!NOTE]
> गेम रुका होने पर बटन जो करता है, वह सीन में वैसे ही रह जाता है जैसे आपने उसे हाथ से किया हो, और उसी तरह वापस भी लिया जा सकता है: <kbd>Ctrl</kbd> + <kbd>Z</kbd> बटन ने जो कुछ किया, वह सब एक ही बार में वापस ले लेता है। गेम चलते समय इतिहास में कुछ भी दर्ज नहीं होता: **Stop** दबाने पर सब कुछ पहले जैसा हो जाता है।

स्क्रिप्ट आपस में वेरिएबल शेयर नहीं करतीं। एक-दूसरे को डेटा देने के लिए (पॉइंट, खिलाड़ी जीता या नहीं…) वे एक साझा जगह का इस्तेमाल करती हैं: `setCompartido("puntos", 10)` लिखता है और `compartido("puntos")` पढ़ता है। इसमें संख्याएँ, हाँ/नहीं और टेक्स्ट रखे जा सकते हैं, और गेम रोकने पर यह ख़ाली हो जाती है।
