# 声音和音乐

**W3dAudio** 是一个用 C++03 编写的**软件混音器**，在所有系统上完全相同（与 Quake 用的是同一种思路）。它把最多 64 路声音混合成一条 16 位立体声流，带有线性插值（变调时不会有颗粒感）、峰值限制器、ADSR 包络、混响，以及一个独立的时钟，让音乐音序器不依赖于帧何时运行。

每个系统只提供**输出**：四个函数（`W3dAudioBackendInit`、`Shutdown`、`Lock`、`Unlock`，在 `W3dAudioBackend.h` 中），负责打开设备并向混音器请求下一段数据。

| 系统 | 输出 |
|---|---|
| PC、Android、浏览器 | SDL2（44,100 Hz） |
| Symbian | `CMdaAudioOutputStream`，在自己的线程中运行，使用双缓冲（N95 上为 22,050 Hz） |
| 主机 | 为主机编译的编辑器没有声音。用“Use sound”编译的游戏会带上混音器，并使用 SDL 的输出 |
| Dreamcast | 此外还有 `w3dAICA`：一个直接使用声音芯片的可选模块（64 个硬件通道和 4 位 ADPCM）。它不能与 W3dAudio 共存 |

另外还有三个部分：

- **W3dMusic：** 长音乐（mp3、ogg、aac）不会转换成 PCM：由系统解码，几乎总是用硬件解码。目前它有浏览器后端（一个 `<audio>` 元素）；Symbian 和桌面的后端还没做。
- **W3dClip：** 界面的短音效。在浏览器中通过 WebAudio 播放，因为在 iOS 上用 `<audio>` 触发它们会让手机卡住。在其他系统上，它们是混音器的声音。
- **W3dVolumen：** 总音量和静音对所有发声的内容都有效，并会自动保存到配置中。

为什么重要：Android 上的游戏曾经**没有声音**，尽管 .wav 已经正确打包在 APK 中，因为它们是用 `fopen` 打开的，而在 APK 里它们并不是文件。自从声音改为通过 `ReadFileBytes` 加载，它在所有地方都能正常工作。在 Lua 中：[声音](../lua/api-sonido.md)。
