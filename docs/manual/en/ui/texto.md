# Text

## The bitmap font

The interface font is hand-drawn in `font.png`. Each character is a **5x11**-pixel cell and advances **6** (`CharacterWidth`). A line is **12** tall (`RenglonHeight`). It's monospaced: every character takes up the same space. With scaling, everything is multiplied by `GlobalScale`.

`Font` (`text/font.h`) stores each character's coordinates. There's only one, global: `WhiskFont`. It's created with the atlas size and its texture ([Using the UI directly](empezar.md)).

`font.png` has the letters, the numbers and almost all of ASCII's symbols, plus `ñ`, `Ñ`, `¡`, `°` and the check mark `✔`. Two come from another character flipped: `\` is `/` mirrored and `¿` is `?` rotated, a little lower.

## Accents

Accented letters aren't drawn: they're built from the base letter with the mark on top.

- The **acute** and the **tilde** come from `font.png`: the acute is a crop of the comma, and the tilde is the one from `ñ`. They're a 2-pixel strip, placed higher over a capital letter.
- The other marks (grave, circumflex, diaeresis, dot, breve, cedilla and ogonek) are in the extended atlas.

## The extended atlas

`font-ext.png`, 128x64, has what doesn't fit in `font.png`:

- the accent marks,
- `ß`, `ı`, `ł`, `Ł`, `œ`, `Œ`, `æ` and `Æ`,
- `;`, `^`, `~`, `` ` ``, `±`, `«`, `»`, `–`, `—` and `…`,
- **Cyrillic**. The letters identical to a Latin one (`А В Е К М Н О Р С Т Х` and `а е о р с у х`) use the one in `font.png`.

It's only loaded the first time a text needs it: `SetAtlasExtendido` just stores the path. In English or Spanish it may never be loaded, and on the N95 memory counts. If the file is missing, a composed letter comes out without its mark and a character from the extended atlas comes out as `?`.

The tables, with which cell holds each character and how each letter is built, are in `text/FuenteExt.h`. They aren't edited by hand: they're generated by `tools/fuente_ext.py`, which also draws the PNG and is in the editor's repository.

With the two textures you get Spanish, Portuguese, French, German, Italian, Polish, Turkish and Russian. Japanese, Chinese and Hindi don't fit: whatever isn't in any atlas comes out as `?`. `WhiskFont->Soporta(cp)` says whether a character can be drawn.

Text is UTF-8. `UTF8_Char` reads sequences of 1 to 3 bytes. A 4-byte one, like an emoji, can't be read: it comes out as question marks.

## Drawing a text

```cpp
SetColorID(ColorID::blanco);
RenderBitmapText("Hola", textAlign::left, 200);   // 200: the maximum width, in pixels
```

It's drawn at the origin of the current matrix, with the current color. Each text is one draw call per atlas: one, or two if it uses the extended one. When it finishes it binds the `font.png` texture again, so the icons that come next find it.

## Measuring and cutting

The width of a text is the number of letters times `CharacterWidthGS`. `UTF8_Largo(texto)` counts letters, not bytes: an `ñ` takes two bytes and counts as one.

If it doesn't fit in the maximum width, `RenderBitmapText` cuts it:

| Alignment | Where it goes | What gets cut |
|---|---|---|
| `textAlign::left` | Starts at the origin | The end |
| `textAlign::right` | Ends at the origin | The beginning: in a field you see the last thing typed |
| `textAlign::center` | Centered in the maximum width | The end |

`RenderBitmapEtiqueta(texto, ancho)` is for a row's label: it's right-aligned, but if it doesn't fit it cuts the end and adds `..` ("Vectores de movimi..").

`RenderBitmapFloat(valor, alineación, ancho, unidad)` draws a number with four decimals and the unit right after it: `90.0000°`. It doesn't use `%f`, because Symbian's `printf` doesn't format `float`.

## Text with TTF fonts

For freely sized letters there's `w3dui::W3dTextAtlas` (`text/W3dTextAtlas.h`). It's header-only. It draws a TTF font already baked into an atlas, and each letter is scaled and positioned on its own: it's good for titles, scores and animated letters. It doesn't rasterize the TTF at runtime.

The atlas is baked on PC with `text/bake_atlas.py`, which needs Pillow: `bake_atlas.py <fuente.ttf> <lado del atlas> <alto de letra> <salida>`. The atlas side is 128, 256, 512 or 1024. It bakes ASCII and `áéíóúÁÉÍÓÚñÑüÜ¿¡`. Out come `<salida>.png`, with the coverage in grayscale and no alpha, and `<salida>.w3dfnt`, with each letter's measurements.

```cpp
#include "WhiskUI/text/W3dTextAtlas.h"
#include "io/w3dFilesystem.h"

std::vector<unsigned char> fnt, png;
w3dFileSystem::ReadFileBytes("fuentes/titulo.w3dfnt", fnt);
w3dFileSystem::ReadFileBytes("fuentes/titulo.png", png);

w3dui::W3dTextAtlas titulo;
titulo.Load(&fnt[0], fnt.size(), &png[0], png.size());

titulo.Begin();                                                // atlas, blending and state
titulo.DrawText("Puntaje: 120", 10, 10, 24, 1, 1, 1, 1);      // x, y, height, r, g, b, a
float ancho = titulo.TextWidth("Puntaje: 120", 24);
```

`(x, y)` is the top of the line, with Y pointing down. `DrawText` puts all the letters in a single draw. `DrawGlyph` draws just one, for letters of different sizes or colors. `LineHeight(alto)` gives the height of a line. By default it blends with premultiplied alpha (`MezclaPremult`): the text can be any color.

## The table without the GPU

`text/W3dFont.h` has the same bitmap font table, without touching the GPU: where each letter is in `font.png` (`W3dFontGetGlyphPx`) and its coordinates (`W3dFontGetGlyph`). It's useful for building another atlas with the same font.
