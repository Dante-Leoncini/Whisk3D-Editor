# Цвета и масштаб

## Палитра

Цвета UI — это роли, а не фиксированные цвета: enum `ColorID` (`theme/colores.h`).

| Роль | Для чего используется |
|---|---|
| `background` | Фон. Квадратик выключенного флажка и рамка кнопки в покое |
| `blanco` | Текст и рамка того, что под мышью или выбрано |
| `accent` | Фокус: рамка меню, то, что сейчас редактируется, активный пункт, заливка ползунка |
| `accentDark` | Фон выделенного текста и полоса числовой кнопки |
| `negro` | Линия `PropSeparator` |
| `gris` | Тело карточек, кнопок и меню |
| `headerColor` | Подсвеченная строка меню и дорожка ползунка |
| `negroTransparente` | Чёрный на 25 %. UI его не использует |
| `grisUI` | Обычный текст и квадратик включённого флажка |
| `grisLinea` | Линии, разделяющие группы в меню |

`ListaColores` хранит их во `float`, а `ListaColoresUbyte` — в байтах. `SetColorID` устанавливает один из них цветом рисования, с необязательной альфой:

```cpp
SetColorID(ColorID::accent);         // непрозрачный
SetColorID(ColorID::grisUI, 0.5f);   // с половинной непрозрачностью
```

`loadColorsW3d(ruta)` читает их из текстового файла, по одному цвету на строку: имя и четыре компонента от 0 до 1, например `accent 0.0 1.0 0.0 1.0`. Незнакомые имена игнорируются, поэтому тот же `skin.ini` может содержать цвета другой программы. Возвращает `false`, если не удалось открыть файл. Без файла остаются цвета из кода (`theme/colores.cpp`); скин Whisk3D их меняет, и, например, `accent` становится зелёным.

Некоторые цвета прописаны в коде и не берутся из палитры: зелёный цвет ромба несохранённого изменения, красный у `PropLabel` с ошибкой, красная рамка незаполненного `PropText` и серый у неактивного `PropButton`.

## Масштаб

Базовые размеры находятся в `core/UI.h`, в пикселях:

| Размер | Значение |
|---|---|
| `margin`, `padding` | 10 |
| `border` | 4 |
| `gap` | 5 |
| `RenglonHeight` | 12 |
| `LetterWidth`, `CharacterWidth` | 6 |
| `LetterHeight` | 11 |

`GlobalScale` умножает их, всегда на целое число: так пиксельные буквы остаются чёткими. Например, 1 на 240-пиксельном экране N95 и 3 на ПК.

У каждого размера есть уже умноженная версия, с `GS` на конце: `RenglonHeightGS`, `gapGS`, `borderGS`, `bordersGS` (двойная рамка), `CharacterWidthGS`, `LetterHeightGS`... Виджеты используют именно их.

Функции, которая их пересчитывает, в UI нет: у редактора это `SetGlobalScale`, в `main/ui/ViewPorts/ViewPorts.cpp`. Без редактора это делается так:

```cpp
void Escala(int s) {
    GlobalScale = s;
    marginGS = margin * s;  paddingGS = padding * s;  gapGS = gap * s;
    borderGS = border * s;  bordersGS = borderGS * 2;
    RenglonHeightGS = RenglonHeight * s;
    LetterWidthGS = LetterWidth * s;  LetterHeightGS = LetterHeight * s;
    CharacterWidthGS = CharacterWidth * s;
    SetIconScale(s);
    if (WhiskFont) WhiskFont->SetScale(s);
}
```

Размеры каждого виджета вычисляются в его `Resize`: после смены масштаба его нужно снова вызвать для каждой карточки, кнопки и меню.

## Компактный или сенсорный

`UIBotonAltura()` даёт высоту кнопки, а `UIBarPadding()` — отступ сверху и снизу от кнопки на панели. Оба зависят от `UITactil`:

- `false` — компактный режим, рассчитанный на N95: кнопка имеет высоту строки текста плюс рамки, минус `2 * GlobalScale`, а панель оставляет `GlobalScale` сверху и снизу.
- `true`: кнопка и панель добавляют `gap`, чтобы помещался палец. Рамки не утолщаются.

`UITactil` начинается с `false`, и сейчас её ничто не включает.
