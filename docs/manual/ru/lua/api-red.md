# Сетевая игра (LAN, Wi-Fi или интернет)

У сетевой партии есть **хост** (тот, кто её создаёт: игрок 0) и те, кто **присоединяется** (1, 2…). Всё проходит через
хоста: игрок отправляет данные хосту, а хост раздаёт их остальным. Те, кто в одной сети (в одной LAN или в одной
Wi-Fi-сети), находят друг друга сами; через интернет нужно присоединяться по адресу хоста (и у него на роутере должен
быть открыт порт 47023).

| Функция | Что делает |
|---|---|
| `redDisponible() → bool [, motivo]` | Может ли эта игра использовать сеть. Если нет — причина: `"sin permiso"` (редактор не дал этому проекту разрешение) или `"sin red"` (на этой платформе сети пока нет). |
| `redDispositivo() → texto` | Имя этого устройства (его видят другие, когда ищут партии). Меняется в редакторе: карточка **Настройки**, *Имя устройства*. |
| `redDireccion() → texto` | IP этого устройства в локальной сети (чтобы присоединиться через интернет или вписать его вручную). |
| `redHostear(nombre [, maximo [, juego]]) → bool [, error]` | Создаёт партию и ждёт игроков (`maximo` с учётом хоста: по умолчанию 2). `juego` — название твоей игры: видны только партии той же игры. |
| `redAbrir(bool)` | Хост появляется в поиске и принимает игроков (`true`) или нет (например, когда партия уже началась). |
| `redBuscar([juego]) → bool` | Начинает искать партии в локальной сети. Повторный вызов **обновляет** список. |
| `redPartidas() → { {nombre, dispositivo, jugadores, maximo, direccion}, … }` | Партии, которые ответили (список обновляется сам, пока ты ищешь). |
| `redUnirse(direccion) → bool` | Входит в партию: `direccion` из `redPartidas()` или введённый адрес (`"192.168.0.10"`, `"x.x.x.x:puerto"`). |
| `redEstado() → estado, error` | `"nada"`, `"buscando"`, `"esperando"` (ты хост), `"conectando"`, `"conectado"` или `"error"` (с причиной). |
| `redYo() → id` | Твой номер в партии (0 = хост; -1 — нет партии). |
| `redJugadores() → { {id, nombre, yo}, … }` | Те, кто в партии (имя — это имя их устройства). |
| `redSilencio([id]) → segundos, limite` | Сколько времени от этого игрока ничего не приходит (без `id`: от того, кто молчит дольше всех). Присоединившийся слышит только хоста, поэтому для него это молчание хоста. После `limite` (8 с) игрок считается ушедшим: хост убирает его из партии, а у присоединившегося `redEstado()` возвращает `"error"`. |
| `redEnviar(valor [, para [, confiable]]) → bool` | Отправляет значение Lua (число, текст, логическое значение или таблицу, в том числе с вложенными таблицами) одному игроку (`para` = его id) или всем (`nil`). **Надёжно** (по умолчанию): доходит гарантированно и по порядку. С `false` не отправляется повторно, если потерялось: для того, что ты отправляешь каждый кадр (позиции, геймпад), где следующее сообщение заменяет предыдущее. |
| `redRecibir() → { {de, datos}, … }` | Всё, что пришло с прошлого раза, по порядку. |
| `redCerrar()` | Выходит из партии (у хоста — закрывает её для всех). Stop в редакторе тоже её закрывает. |

## Разрешение

Проект, который создаёт партии, ищет их или присоединяется к ним, не выходит в сеть, пока пользователь этого не разрешит.
При открытии проекта (или при нажатии Play, если он начал использовать сеть позже) редактор спрашивает **только один раз**
для каждого файла и запоминает ответ. Позже это можно изменить в карточке **Файл**: *Доступ к сети*. Без разрешения игра
всё равно работает, а `redDisponible()` возвращает `false, "sin permiso"`: покажи сообщение вместо пункта сетевой игры.

## Пример: лобби

```lua
local JUEGO = "mi_juego"

function inicio()
  if not redDisponible() then info("sin red") return end
  if propiedad("anfitrion") then redHostear(redDispositivo(), 2, JUEGO) else redBuscar(JUEGO) end
end

function actualizar(dt)
  local estado = redEstado()
  if estado == "buscando" then
    local p = redPartidas()
    if p[1] then redUnirse(p[1].direccion) end
  end
  if teclaApretada("enter") then redEnviar({t = "listo"}) end
  for _, m in ipairs(redRecibir()) do
    if m.datos.t == "listo" then info("el jugador " .. m.de .. " esta listo") end
  end
end
```

## Советы

- **Один расчёт**: проще всего и лучше всего между разными устройствами (ПК и телефоном) работает, когда хост
  рассчитывает игру и отправляет остальным то, что они должны показать; остальные отправляют ему только свой геймпад.
  Так сделано в демо Dragon Ball (`dbz2w3d/lua/pelea.lua`).
- То, что отправляется каждый кадр, — **ненадёжно**; то, что происходит один раз (уведомление, «начать»), — **надёжно**.
- **Когда сеть подвисает**: если в бою `redSilencio()` превышает несколько десятых секунды, другой игрок перестал
  отправлять данные (оборвался Wi-Fi, телефон ушёл в фон). Поставь игру на паузу и сообщи об этом («ожидание…», с
  оставшимся до `limite` временем): если он вернётся, игра продолжится с того же места; если нет, об этом скажут
  `redEstado()` или `redJugadores()`.
- Отправляй только необходимое: числа и короткие тексты. Сообщение не может быть больше 60000 байт.
- В браузере сети пока нет (там нет UDP). Android требует разрешение `INTERNET` (собранная игра его содержит);
  Symbian — возможность `NetworkServices` (телефон спрашивает, через какую точку доступа выходить).
