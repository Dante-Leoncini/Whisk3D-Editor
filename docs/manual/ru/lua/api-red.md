# Сетевая игра (LAN, Wi-Fi или интернет)

У сетевой партии есть **хост** (тот, кто её создаёт: игрок 0) и те, кто **присоединяется** (1, 2…). Всё проходит через
хоста: игрок отправляет данные хосту, а хост раздаёт их остальным. Те, кто в одной сети (в одной LAN или в одной
Wi-Fi-сети), находят друг друга сами; через интернет нужно присоединяться по адресу хоста (и у него на роутере должен
быть открыт порт 47023).

| Функция | Что делает |
|---|---|
| `netAvailable() → bool [, reason]` | Может ли эта игра использовать сеть. Если нет — причина: `"no permission"` (редактор не дал этому проекту разрешение) или `"no network"` (на этой платформе сети пока нет). |
| `netDevice() → text` | Имя этого устройства (его видят другие, когда ищут партии). Меняется в редакторе: карточка **Настройки**, *Имя устройства*. |
| `netAddress() → text` | IP этого устройства в локальной сети (чтобы присоединиться через интернет или вписать его вручную). |
| `netHost(name [, max [, game]]) → bool [, error]` | Создаёт партию и ждёт игроков (`max` с учётом хоста: по умолчанию 2). `game` — название твоей игры: видны только партии той же игры. |
| `netOpen(bool)` | Хост появляется в поиске и принимает игроков (`true`) или нет (например, когда партия уже началась). |
| `netFind([game]) → bool` | Начинает искать партии в локальной сети. Повторный вызов **обновляет** список. |
| `netMatches() → { {name, device, players, max, address}, … }` | Партии, которые ответили (список обновляется сам, пока ты ищешь). |
| `netJoin(address) → bool` | Входит в партию: `address` из `netMatches()` или введённый адрес (`"192.168.0.10"`, `"x.x.x.x:puerto"`). |
| `netState() → state, error` | `"none"`, `"searching"`, `"waiting"` (ты хост), `"connecting"`, `"connected"` или `"error"` (с причиной). |
| `netSelf() → id` | Твой номер в партии (0 = хост; -1 — нет партии). |
| `netPlayers() → { {id, name, isSelf}, … }` | Те, кто в партии (имя — это имя их устройства). |
| `netSilence([id]) → seconds, limite` | Сколько времени от этого игрока ничего не приходит (без `id`: от того, кто молчит дольше всех). Присоединившийся слышит только хоста, поэтому для него это молчание хоста. После `limite` (8 с) игрок считается ушедшим: хост убирает его из партии, а у присоединившегося `netState()` возвращает `"error"`. |
| `netSend(value [, para [, reliable]]) → bool` | Отправляет значение Lua (число, текст, логическое значение или таблицу, в том числе с вложенными таблицами) одному игроку (`para` = его id) или всем (`nil`). **Надёжно** (по умолчанию): доходит гарантированно и по порядку. С `false` не отправляется повторно, если потерялось: для того, что ты отправляешь каждый кадр (позиции, геймпад), где следующее сообщение заменяет предыдущее. |
| `netReceive() → { {from, data}, … }` | Всё, что пришло с прошлого раза, по порядку. |
| `netClose()` | Выходит из партии (у хоста — закрывает её для всех). Stop в редакторе тоже её закрывает. |

## Разрешение

Проект, который создаёт партии, ищет их или присоединяется к ним, не выходит в сеть, пока пользователь этого не разрешит.
При открытии проекта (или при нажатии Play, если он начал использовать сеть позже) редактор спрашивает **только один раз**
для каждого файла и запоминает ответ. Позже это можно изменить в карточке **Файл**: *Доступ к сети*. Без разрешения игра
всё равно работает, а `netAvailable()` возвращает `false, "no permission"`: покажи сообщение вместо пункта сетевой игры.

## Пример: лобби

```lua
local GAME = "mi_juego"

function start()
  if not netAvailable() then info("sin red") return end
  if property("anfitrion") then netHost(netDevice(), 2, GAME) else netFind(GAME) end
end

function update(dt)
  local state = netState()
  if state == "searching" then
    local p = netMatches()
    if p[1] then netJoin(p[1].address) end
  end
  if keyPressed("enter") then netSend({t = "listo"}) end
  for _, m in ipairs(netReceive()) do
    if m.data.t == "listo" then info("el jugador " .. m.from .. " esta listo") end
  end
end
```

## Советы

- **Один расчёт**: проще всего и лучше всего между разными устройствами (ПК и телефоном) работает, когда хост
  рассчитывает игру и отправляет остальным то, что они должны показать; остальные отправляют ему только свой геймпад.
  Так сделано в демо Dragon Ball (`dbz2w3d/lua/pelea.lua`).
- То, что отправляется каждый кадр, — **ненадёжно**; то, что происходит один раз (уведомление, «начать»), — **надёжно**.
- **Когда сеть подвисает**: если в бою `netSilence()` превышает несколько десятых секунды, другой игрок перестал
  отправлять данные (оборвался Wi-Fi, телефон ушёл в фон). Поставь игру на паузу и сообщи об этом («ожидание…», с
  оставшимся до `limite` временем): если он вернётся, игра продолжится с того же места; если нет, об этом скажут
  `netState()` или `netPlayers()`.
- Отправляй только необходимое: числа и короткие тексты. Сообщение не может быть больше 60000 байт.
- В браузере сети пока нет (там нет UDP). Android требует разрешение `INTERNET` (собранная игра его содержит);
  Symbian — возможность `NetworkServices` (телефон спрашивает, через какую точку доступа выходить).
