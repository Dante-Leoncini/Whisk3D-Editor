# 入力

ほとんどのシステムでは、キーボード、マウス、指、ゲームパッドの入力を**SDL2**が届けていて、エディターもゲームもそのイベントの上に書かれています。SDLが扱わない部分はCoreが補います：

| 入力 | どう届くか |
|---|---|
| タッチ | Android、ブラウザー、Vita、3DSではSDL。Symbianでは、`W3dTactil`がSDLと同じ変換をします（最初の指はマウスを動かし、ほかの指は指として通知されます）。S60 5thは指1本、N8はマルチタッチ |
| 傾き | N95では、起動時に読み込むNokiaのSensor API（なくてもゲームはそのまま動きます）。AndroidとPCではSDL経由 |
| ゲームパッド | それ以外はSDL。Symbianでは、Bluetooth接続のPS3とPS4のコントローラー（bthid-s60ドライバー）を、SDLと同じボタンの順番で使えます。最大4台 |
| 振動 | Androidは電話のバイブレーター。ブラウザーは`navigator.vibrate`（iOSでは、ちょっとした工夫でシステムの「カチッ」という触覚）。デスクトップでは何もしません。APIが約束するのは「できれば短く1回」だけです |
| クリップボード | SDL（ブラウザーのものも含む）。Symbianでは`CClipboard` |

タッチスクリーンのないコンソール（PSP、Dreamcast）では、コントローラーでマウスのようにカーソルを動かします。

これが重要な理由：Symbianのタッチ操作のジェスチャーはAndroidと同じ経路を通るので、Androidでジェスチャーを改良すると、それがそのまま電話にも反映されます。Luaからは：[キーボード、ゲームパッド、タッチ、マウス](../lua/api-entrada.md)。
