# サウンドと音楽

**W3dAudio**はC++03で書かれた**ソフトウェアミキサー**で、すべてのシステムで同じものが動きます（Quakeが使っていたのと同じ考え方です）。最大64ボイスを16ビットのステレオストリームにミキシングします。線形補間（ピッチを変えても音がざらつきません）、ピークリミッター、ADSRエンベロープ、リバーブに加えて、独自のクロックを持っているので、音楽のシーケンサーはフレームがいつ実行されるかに左右されません。

各システムが用意するのは**出力**だけです：`W3dAudioBackend.h`にある4つの関数（`W3dAudioBackendInit`、`Shutdown`、`Lock`、`Unlock`）で、デバイスを開き、ミキサーに次の分のデータを要求します。

| システム | 出力 |
|---|---|
| PC、Android、ブラウザー | SDL2（44,100 Hz） |
| Symbian | 専用のスレッドで動く`CMdaAudioOutputStream`。ダブルバッファー（N95では22,050 Hz） |
| コンソール | コンソール向けにビルドしたエディターには音がありません。「Use sound」でビルドしたゲームには、SDLの出力を使うミキサーが入ります |
| Dreamcast | さらに`w3dAICA`があります：サウンドチップを直接使うオプションのモジュールです（ハードウェアで64チャンネル、4ビットADPCM）。W3dAudioとは併用できません |

ほかに3つの部品があります：

- **W3dMusic：** 長い音楽（mp3、ogg、aac）はPCMに変換しません。デコードはシステムが行い、ほとんどの場合はハードウェアで処理されます。現在バックエンドがあるのはブラウザー（`<audio>`要素）だけで、Symbianとデスクトップのものは未対応です。
- **W3dClip：** インターフェースの短い効果音。ブラウザーではWebAudioを使います。iOSでは`<audio>`で鳴らすと電話が固まってしまうからです。それ以外では、ミキサーの効果音です。
- **W3dVolumen：** 全体の音量とミュートは、鳴っているものすべてに効き、設定に自動で保存されます。

これが重要な理由：Androidのゲームは、.wavがAPKの中に正しく入っていたのに**無音**になっていました。`fopen`で開いていたからで、APKの中ではそれらはファイルではないのです。サウンドを`ReadFileBytes`で読み込むようにしてからは、どこでも鳴るようになりました。Luaからは：[サウンド](../lua/api-sonido.md)。
