# スクリプトはオブジェクトのコンポーネント

Whisk3Dでは、スクリプトは必ずシーン内の**オブジェクト**（メッシュ、エンプティ、2Dボタン…）に属します。1つのオブジェクトに複数のスクリプトを付けられます。それぞれが独自の変数を持ち、表示されている順に別々に実行されます。

スクリプトの中では、`self()`で持ち主のオブジェクトを取得できます。*ほかの*オブジェクトを使うには、スクリプトで`properties`という名前のグローバルテーブルを宣言します。エディターはこれを読み取り、Propertiesパネルのスクリプトのカードに、項目ごとにフィールドを表示します：

```lua
properties = {
  ball       = "object",                          -- シーンのオブジェクトを選ぶフィールド
  difficulty = { "facil", "normal", "dificil" },  -- ドロップダウンリスト（最初の項目が初期値）
  speed      = 200,                               -- このスクリプトを使う各オブジェクトが個別に持つ数値
  active     = true,                              -- はい/いいえ
  label      = "caja",                            -- テキスト
}

function start()
  local p   = object("ball")         -- 「pelota」フィールドで選んだオブジェクト
  local dif = option("difficulty")   -- "facil"、"normal"、"dificil"のいずれか
  local v   = property("speed")      -- 200、またはそのオブジェクトで設定した値
end
```

**名前で読む：** プロパティは名前を書くだけでも読めます。`speed` は `property("speed")` と、`difficulty` は `option("difficulty")` と、`ball` は `object("ball")` と同じです。その時点の値を読むので、ゲーム実行中にプロパティパネルで変えた値も反映されます。例外が2つあります。スクリプトに同じ名前の変数がある場合（`speed = 5`）は変数が優先されます。また、プロパティが Whisk3D の関数と同じ名前（たとえば `target` や `view`）の場合、その名前は関数を指すので、`property()`、`option()`、`object()` で読んでください。

> [!NOTE]
> `properties`を読み取るために、エディターはゲームが実行されていなくても**ファイルを実行します**。そのため、関数の外には宣言（テーブル、定数、`local`）だけを書き、何かを実行するコードは決して書かないでください。

Propertiesのスクリプトのカードでは、次のように表示されます。プロパティごとにフィールドが1つずつ、コードと同じ順番で並びます。

こうすることで、同じスクリプトを、値の異なる多くのオブジェクトに使えます。ある敵の`speed`フィールドは200、別の敵は350、といった具合です。

## プロパティをリアルタイムで変更する

`property("speed")`は、その時点の値を読み取ります。ゲームの実行中にPropertiesで値を変えると、スクリプトは次のフレームで新しい値を受け取ります。ただし、`property()`でもう一度読み取る場合に限ります。変数に保存していた場合（`start()`の中の`local v = property("speed")`）は、変数は最初の値のままです。

```lua
function update(dt)
  -- 毎フレーム読み取る：ゲームの実行中にPropertiesで変えた値が反映される
  move(self(), property("speed") * dt, 0, 0)
end
```

毎フレーム`property()`を読み取るのは、変数を使うより遅くなります。ゲーム全体をこの方法で作るのはおすすめしません。値を調整している間だけ使い、値が決まったら`start()`で変数に保存しましょう。

## ボタン

プロパティが**関数**の場合、カードに**ボタン**が表示され、押すとその関数が呼ばれます。ボタンに名前以外の文字を表示するには、テキストと関数をテーブルに入れます：

```lua
properties = {
  speed    = 90,
  zero = { "ゼロに戻す", function()
    setRotation(self(), 0, 0, 0)
  end },
}
```

![velocidadと「ゼロに戻す」ボタンがあるスクリプトのカード](../tutoriales/img/lua-boton.webp)

ゲームの実行中は、関数はプレイ中のスクリプトで実行されます。ゲームを実行していないときは、その呼び出しのためだけにスクリプトが読み込まれます。そのため、ボタンはシーンに何かをする**エディターのアドオン**として使えます。たとえば、エディターで選択したオブジェクトを返す`selected()`を使うと：

```lua
properties = {
  upload = { "選択したものを上げる", function()
    for _, o in ipairs(selected()) do
      move(o, 0, 0, 1)   -- 1メートル上へ
    end
  end },
}
```

> [!NOTE]
> ゲームを止めているときにボタンが行ったことは、手で操作したときと同じようにシーンに残り、同じように元に戻せます。<kbd>Ctrl</kbd> + <kbd>Z</kbd> で、ボタンが行ったことをまとめて一度に元に戻せます。ゲームの実行中は履歴に何も記録されません。**Stop** を押すと、すべて元の状態に戻ります。

スクリプト同士は変数を共有しません。データ（得点、プレイヤーが勝ったかどうか…）を受け渡すには、共有領域を使います：`setShared("puntos", 10)`で書き込み、`getShared("puntos")`で読み取ります。数値、はい/いいえ、テキストを保存でき、ゲームを停止すると空になります。
