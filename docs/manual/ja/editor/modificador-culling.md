# Culling

**Culling**モディファイアーは、メッシュの三角形のうち、カメラのいるエリアから見えるものだけを描画します。PlayStation 1のゲームと同じように、エリアごとにあらかじめ計算した可視リストを使います（**PVS**、*潜在的可視集合*）。大きなステージに向いています。レベル全体のうち、今いる廊下から見えるものだけが描画されます。

![Nokia](../tutoriales/img/icono-nokia.svg) Nokia N95向けに作られています。N95では、描画しない三角形が1つ増えるごとに速度が上がります。エリアの切り替えにはほとんどコストがかかりません。リストは一度だけ作られ、エリアを移るときは、どのリストを使うかが変わるだけです。フレームごとの計算はありません。

![Modifiersタブ全体。立方体にCullingモディファイアーが付いています](../tutoriales/img/modificador-culling.webp)

## 追加のしかた

1. ステージのメッシュを選択します。
2. Propertiesで**Modifiers**タブ（スパナのアイコン）を開きます。
3. **Add**をタップして、**Culling**を選びます。

リストには内部名の**Oclusion**で表示され、その下にパラメーターのカードが開きます。メッシュには手を加えず、どの三角形を描画するかを選ぶだけなので、メッシュは元のまま編集できます。そのため、Apply Modifierはありません。

3D ViewportのAddメニューにある**Culling**オブジェクトと混同しないでください。そちらは、メッシュの三角形ではなく、オブジェクト全体を単位に処理します。

## データの出どころ

このモディファイアーは、何が見えるかを自分では計算しません。モデルに付属するファイルから読み込みます。`nivel.obj`から読み込んだメッシュなら、同じフォルダーにある`nivel.pvs.json`を探します。

```json
{ "sectores": 2, "tris": [[0, 1], [2, 3]] }
```

`sectores`はエリアの数で、`tris`には、エリアごとに描画する三角形が入っています。三角形の番号は、`.obj`の面の順番で0から数えます。ふつうは、元のゲームや別のツールから持ってきます。各エリアは**ノード**です。ノード1が最初のリストで、ノード0はメッシュ全体を描画します。

## パラメーター

| パラメーター | 働き |
|---|---|
| Display in Viewport | オフにすると、メッシュ全体が描画されます。 |
| Display in Edit Mode | 何も変わりません。Edit Modeでは、メッシュは常に全体が描画されます。 |
| Method | **Triangles (PVS)**は`.pvs.json`のリストを使います。**BSP (pending)**はグレーで表示され、まだ選べません。 |
| Recalculate | `.pvs.json`を読み込み直します。たとえば、ファイルを作り直したあとに使います。「PVS recalculated」と表示され、ファイルが見つからないときは「PVS: <model>.pvs.json is missing next to the source .obj」と表示されます。 |
| （状態の行） | Recalculateの下に表示されます。「4 nodes \| active node: 2」、ファイルがないときは「no data (whole mesh)」、または「sidecar not loaded (Recalculate)」。 |
| Path | シーンのパス（**Add → Path**）です。たとえば、カメラが通るレールです。パスの各ノードが1つのエリアで、エンジンが目にいちばん近いノードを自動で選びます。**None**のときは、エリアを手で、またはスクリプトから設定します。 |
| Only active camera | オン（初期設定）のときは、シーンの再生中はアクティブなカメラが基準になります。一時停止中は自動では何も選ばれず、ノードは手で設定します。オフのときは、ビューポートのビューが基準になります。ステージの中を自由に飛び回って、三角形が現れたり消えたりする様子を確認できます。 |
| Branches | パスに2つ以上の分岐があるときだけ表示されます。たとえば、メインの道とボーナスの道です。いちばん近いノードを探すときに、どの分岐を対象にするかを選びます。オンの分岐は緑で表示されます。ボタンには、たとえば「Branches: 3 (all)」や「Branches: 2/3」と表示されます。 |
| Current node | 描画しているエリアです。0 = メッシュ全体。手で変更して、各エリアを確認できます。Pathがノードを自動で選んでいるときは、エンジンがこの値を上書きします。 |

スクリプトからは、`setSector(objeto, n)`でアクティブなノードを変更できます（0 = メッシュ全体）。[パーティクル、フォグ、可視性](../lua/api-particulas-niebla.md)を参照してください。

## 知っておくとよいこと

- メッシュがEdit Modeのあいだは、すべてを編集できるように、全体が描画されます。
- リストの中に、ジオメトリを生成するオンのモディファイアー（[Mirror](modificador-espejo.md)、[Array](modificador-array.md)、[Subdivision Surface](modificador-subdivision.md)…）がほかにあると、Cullingは使われず、すべてが描画されます。`.pvs.json`の三角形の番号は、元のメッシュのものだからです。
- リストは三角形を番号で指定しています。メッシュを編集して面を追加したり削除したりすると、番号が変わり、リストが別の三角形を指してしまうことがあります。Cullingは完成したステージのためのもので、まだモデリング中のステージには向きません。
