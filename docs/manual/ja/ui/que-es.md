# Whisk3D UIとは

**Whisk3D UI**は、インターフェースを組み立てるためのC++のライブラリです：ボタン、タブ、ドロップダウンメニュー、プロパティのカード、テキスト、アイコン。専用のリポジトリ[Whisk3D-UI](https://github.com/Dante-Leoncini/Whisk3D-UI)があり、MITライセンスです。[Whisk3D Core](../core/README.md)の上に作られていて、Whisk3Dのエディターはこのライブラリで作られています。

![Whisk3Dの構成：どちらも必須ではないEditorとWhisk3D UIが、Whisk3D Coreの上にあります。Coreは各システムとそれぞれのバックエンドを通してやり取りします](img/whisk3d-capas.webp)

## 動く場所

Coreと同じシステムで動きます：**Windows**、**Linux**、**macOS**、**Android**、**ブラウザー**、**Nokia N95**と**N8**、**Sega Dreamcast**、**Sony PSP**、**PS Vita**、**Nintendo 3DS**。エディターはそのすべてでこのライブラリをコンパイルしています。

UIには、システムごとの独自コードがありません。OpenGLは呼ばず、すべてを`w3dEngine`の関数（[グラフィックス](../core/graficos.md)）で描画し、残りは各システムのバックエンドが処理します。システムによって変わるわずかな部分は、コンパイルに関するものです：

- ヘッダーは、型（`GLfloat`、`GLshort`、`GLubyte`）のために`GL/gl.h`を、Symbianでは`GLES/gl.h`をインクルードします。
- Androidでは、`loadColorsW3d`はバイトの色テーブルを更新しますが、`float`のテーブルは更新しません。
- SymbianのコンパイラーはC++11を知らないので、コードはC++03です：enumは`struct`の中に入れ（`IconType::camera`）、`override`の代わりに`W3D_OVERRIDE`を使います。

## なぜベクターではなくアトラスなのか

ほとんどのインターフェースのライブラリは、ベクターで描画します。古い機器の多くはそれをハードウェアで高速化できないため、インターフェースはソフトウェアで描画され、動作が遅くなります。一方、N95のような機器が高速化できるのは3D、つまりテクスチャ付きの三角形です。

そのため、Whisk3D UIはすべてを、1枚のテクスチャ、つまり**アトラス**から読む三角形で描画します。文字も、カードの角丸の縁も、アイコンも同じテクスチャにあるので、インターフェース全体が1回の`BindTexture`で済みます。テキストは1文字ごとではなく、アトラス1枚につき1回の呼び出しで描画します。

その代償として、文字はピクセルでできていて、拡大は整数倍でしかできません（[色とスケール](tema.md)）。また、使える文字はアトラスに描かれているものだけです（[テキスト](texto.md)）。

## 中身

| フォルダー | 役割 |
|---|---|
| `core/` | インターフェースの寸法とそのスケール（`UI.h`）：[色とスケール](tema.md) |
| `theme/` | カラーパレット（`colores.h`）：[色とスケール](tema.md) |
| `draw/` | 2D描画（`glesdraw`）、矩形、アイコン、アトラスのパッカー：[描画とアトラス](dibujo.md)、[アイコン](iconos.md) |
| `text/` | ビットマップフォント、拡張アトラス、ベイク済みのTTFフォントによるテキスト：[テキスト](texto.md) |
| `widgets/` | 枠付きのカード、ボタン、タブ、メニュー、テキストボックス：[ボタン、タブ、チェックボックス](botones.md)、[ドロップダウンメニュー](menus.md)、[入力とテキストボックス](entrada.md) |
| `Propieties/` | プロパティのカードとその行：[カードとプロパティ](propiedades.md) |
